## 1. ภาพรวมสถาปัตยกรรม

ระบบเป็นแบบ **หลาย frontend + backend เดียว + ฐานข้อมูลเดียว**

```
นักเรียน (มือถือ/คอม)
        │
        ├──► แอปข้อสอบ (Vercel: wihokwipan) ─┐
        └──► แอปร้านค้า (Vercel: wipan-shop) ─┤
                                              │
                            /api/proxy (Vercel Edge Cache)
                                              │
                              Google Apps Script Web App
                                   (ไฟล์เดียว ~2,300 บรรทัด)
                                              │
                            Google Sheet "Wihok Wiphan" (46 แท็บ)
```

**ทำไมต้องมี proxy:** Google Apps Script รับ request พร้อมกันได้แค่ ~30 อัน
ถ้านักเรียนเข้าพร้อมกันทั้งห้อง (เปิดคาบ / แย่งตีบอส) จะล้น
proxy จึง cache คำขอแบบ "อ่าน" ไว้ที่ Vercel Edge ส่วนคำขอแบบ "เขียน" ส่งตรงเสมอไม่ cache

### กลไกสำคัญที่ต้องรู้
- **Lock เดียวครอบทุกการเขียน** — `doPost` ใช้ `LockService.getScriptLock()` รอคิวได้ 10 วินาที
  ถ้าไม่ว่างจะตอบ `{error:"ระบบกำลังประมวลผลคำขออื่นอยู่..."}` กลับมาแบบ **HTTP 200**
  → ฝั่ง frontend **ต้องเช็ค `res.error` เสมอ** ไม่ใช่แค่ดูว่า request ไม่ throw
- **Google Sheets แปลง string ที่หน้าตาเหมือนวันที่เป็น Date เอง** — เคยทำ Castle Mode พังทั้งระบบ
  แก้ด้วย `_normalizeWeekId()` + `setNumberFormat("@")` — **ถ้าเขียนคอลัมใหม่ที่เป็นรหัสคล้ายวันที่ ต้องทำแบบนี้ด้วย**
- **คอลัมความสำเร็จสร้างอัตโนมัติ** — `ensureAchievementColumns()` สร้างคอลัมของชุดใหม่ให้เอง
  ตั้งแต่ patch 11.1 จำผลไว้ใน Script Properties แล้ว (ไม่สแกนซ้ำทุกครั้ง)
- **ค่าคงที่:** `GACHA_COST = 1000`, `CASTLE_GOLD_PER_LEVEL = 200`, `CASTLE_ARTIFACT_LEVEL_BONUS = 100`
- **Trigger ของ Castle Mode ปิดอยู่** ตามเจตนา (ยังไม่เปิดโหมดปราสาท)

## 6. โครงการถัดไปที่สำคัญที่สุด: ติดป้ายหัวข้อ → วินิจฉัยนักเรียน

**ปัญหา:** ระบบเก็บว่านักเรียนผิดข้อไหน แต่ไม่รู้ว่าข้อนั้นเป็น "เรื่องอะไร" → วินิจฉัยไม่ได้

**แผนที่ทำให้งานนี้เล็กลงมาก:**
1. **ชุดแยกเรื่อง (~606 ข้อ)** → เขียนสคริปต์ดึงเรื่องหลัก/เรื่องย่อยจาก `SetName` ใน QuizConfig มาเติมอัตโนมัติ — **ไม่ต้องทำมือเลย**
2. **ชุดคละ (~315-368 ข้อ)** → ต้องติดป้ายรายข้อ (โจทย์เป็นรูป ต้องอ่านรูป)
3. เสร็จแล้ว → **ผลสอบ ~6,600 ครั้งที่เก็บไว้แล้วถูกวินิจฉัยย้อนหลังทันที**

**ผลลัพธ์ที่ได้:** รู้ว่านักเรียนคนไหนอ่อนเรื่องไหนซ้ำๆ / ทั้งห้องพังตรงไหนเหมือนกัน
→ ต่อยอดเป็น "วินิจฉัย → สั่งยา (คลิปสอน) → สั่งฝึก (ชุดฝึกที่ตรงเรื่อง)" แบบอัตโนมัติ

## 8. ประวัติการแก้ไขสำคัญ

### 8 ต.ค. 2026 — แก้บั๊ก "✗ บันทึกไม่สำเร็จ" (false negative)
นักเรียนเห็นข้อความว่าบันทึกไม่สำเร็จ ทั้งที่ข้อมูลเข้าชีตเรียบร้อย พบ 3 สาเหตุซ้อนกัน:
1. `saveRareProgress` (ของเสริม) ล้มเหลวแล้วลากสถานะของ `saveResult` (ของหลัก) ไปด้วย เพราะอยู่ใน try/catch เดียวกัน
2. Client timeout 20 วิ ไม่เท่ากับ Server ล้มเหลว — Apps Script ทำเสร็จแล้วแต่ตอบช้า
3. (เจอเพิ่ม) Client ไม่เคยเช็ค `res.error` → ตอน Lock ชนกัน Server ตอบ error มาแบบ 200 แต่ Client โชว์ "บันทึกแล้ว" (false positive — อันตรายกว่า)

**แก้:** เพิ่มคอลัม `AttemptID` + `_isDuplicateResultAttempt()` + action `checkResultSaved`
ฝั่ง client แยกสถานะหลัก/เสริม, เช็ค `res.error`, เช็คย้อนกลับก่อนฟันธง, และเพิ่มสถานะ "⚠ ไม่แน่ใจ" (สีส้ม) แทนการฟันธงผิด

### 8 ต.ค. 2026 — ปรับปรุงความเสถียร/ความเร็ว
- **perf:** `ensureAchievementColumns()` จำผลใน Script Properties ไม่สแกน 4 ชีทซ้ำทุกครั้งที่มีคนส่งข้อสอบ → ลดเวลาที่ถือ Lock ต่อ request
- **กันเขียนซ้ำ:** `apiPost` ไม่ fallback ไปยิง DIRECT_SCRIPT_URL ซ้ำถ้ารอบแรกเป็น timeout (แก้ทั้งแอปข้อสอบและร้านค้า)
- **เปิดใช้ dedup ที่ตายอยู่:** `saveBossDamage` ในแอปเดี่ยวไม่เคยส่ง `attemptId` (แต่แอปเดี่ยวเลิกใช้แล้ว — แอปจริงส่งอยู่แล้ว)
- **Castle Mode:** `submitAttack()` ไม่เคยเช็ค `d.error` → เพิ่มแล้ว

## 9. ข้อตกลงการทำงาน

- **ภาษา:** ไทย
- **ระดับความรู้โค้ดของเจ้าของระบบ:** ~0 แต่ตรรกะดีมาก → อธิบายด้วยตรรกะและการเปรียบเทียบ ไม่ใช่ศัพท์เทคนิค
- **การตัดสินใจเชิงออกแบบระบบเป็นของเจ้าของ** — ผู้ช่วยแปลงเป็นโค้ด และต้องเถียงถ้าเห็นว่าออกแบบผิด
- **ส่งงานเป็นไฟล์** ไม่แปะโค้ดยาวในแชท
- **ชื่อไฟล์:** เลี่ยงรูปแบบ `App__NN_.tsx` (ไม่รู้ว่าตัวไหนใหม่) — ใช้ repo เป็นแหล่งความจริง
